## Demo Status

The project is ready for an instructor walkthrough as a working prototype of a school store, debt, accounting, and administrative monitoring system. The strongest demo path is to show role separation first, then demonstrate how one transaction moves through Store POS, User debt visibility, Accounting follow-up, and Admin/Store Admin oversight.

## Main Portals

- Admin Portal: school-wide oversight, users, stores, product oversight, audit logs.
- Store Portal: operational store work such as inventory, POS, open-day, close-day, staff records, history, and reports.
- Store Admin Portal: store-level administrator/supervisor view for assigned stores only, including close-day variance review.
- Accounting Portal: employee debts, advance payments, salary-deduction-oriented settlement, and operator accountability follow-up.
- User Portal: employee/student debt visibility, transaction history, receipts, cashbook, and debt PIN setup/change.

## Implemented Highlights

- Role-based login and role switching for multi-role users.
- Store day must be opened before POS transactions are accepted.
- POS supports stock-aware checkout, debt checkout with debtor PIN, receipts, and direct debt repayment.
- Store close-day compares expected sales against counted cash and e-cash.
- Negative close-day variance can be reviewed by Store Admin and recorded as operator accountability.
- Accounting Debts is now separated into Employee Debts, Advance Payments, and Operator Accountabilities to reduce confusion.
- Admin Products is read-only oversight; operational product changes stay in Store Inventory.
- Store Inventory supports product image update, supplier, bin/location, low-stock threshold, stock-in, and adjustments.
- User Portal includes debt status, history, receipts, and self-service debt PIN flow.

## Suggested Demo Script

1. Login as Admin and show school-wide oversight:
   - Dashboard metrics.
   - Stores and assigned officers/supervisors.
   - Product Oversight as read-only monitoring.
   - Audit Log for accountability.

2. Login as Store Officer and show store operation:
   - Open Store Day.
   - Add/check inventory.
   - Process a POS sale.
   - Process a direct debt repayment if the debtor pays at the store.
   - Close Store Day and show expected versus counted totals.

3. Login as Store Admin and show assigned-store supervision:
   - Dashboard limited to assigned store scope.
   - Review pending close-day variance.
   - Approve a shortage and create operator accountability.

4. Login as Accounting and show financial follow-up:
   - Employee Debts for salary deduction.
   - Advance Payments for direct debtor payments made at stores.
   - Operator Accountabilities for shortage follow-up.

5. Login as User and show employee/student transparency:
   - Current debt and credit limit.
   - Purchase/payment history.
   - Receipt view.
   - Debt PIN setup/change.
