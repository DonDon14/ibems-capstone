## How To Run Locally

Start MySQL from XAMPP, then run:

```powershell
cd D:\xampp\htdocs\ibems-tailwind-test
php spark migrate
php spark serve --port 8080
```

Open:

```text
http://localhost:8080
```

Important: `.env` currently uses `app.baseURL = 'http://localhost:8080/'`. Use `localhost:8080`, not a different port, unless `.env` is changed to match.

## Completed Scope

Phase 1 Store Workflow is complete:

- Daily store opening/closing sessions.
- POS locked unless today's store day is open.
- Store Inventory supports supplier, bin/location, low-stock threshold, duplicate guards, stock-in, adjustments, and product image update.
- POS includes stock-aware checkout, debt PIN verification, projected debt/credit messaging, receipt consistency, direct debt repayment, and payment method loading states.
- Store close-day shows expected cash/e-cash, counted cash/e-cash, variance, and shortage review routing.
- Store Reports/History were reconciled with POS receipt data.

Phase 2 Accounting Workflow is complete:

- Debt list/profile flows.
- CSV import preview validation.
- Settlement preview/apply protections.
- Settlement export/print summary.
- Accounting dashboard KPI and alert improvements.
- Accounting Debts was split into clearer views for employee debts, advance debt payments, and operator accountabilities.

Phase 3 Admin Workflow is complete:

- Admin Dashboard now uses real metrics and operational alerts.
- Store Management supports optional officer assignment, status filtering, and non-redundant card actions.
- Store Details has operational snapshot metrics.
- User Management supports multi-role create/edit/import, credit limit, salary, status, and clearer view/edit behavior.
- Admin Products is now a read-only Product Oversight screen; Store Inventory remains the operational product management surface.
- Admin Audit screen was added for critical audit log review.

Phase 4 User Portal is complete:

- User Dashboard shows debt summary, recent purchases, credit limit, current balance, and debt status.
- User History, Cashbook, and Receipt views were aligned with store/accounting transaction data.
- Users can set or change debt authorization PIN with password verification.

Additional polish completed after Phase 4:

- Store Admin / Store Supervisor portal added for assigned-store oversight.
- Store Admin dashboard shows assigned store metrics and pending shortage/overage review.
- Store Admin can approve close-day variance reviews and create operator accountability records for shortages.
- Store search and input spacing were standardized in the recently touched Store and Accounting screens.
